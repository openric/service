# 2026-10-26 - v0.17.27: record hierarchy, record dates, autocomplete types, root hidden

Author: Dr Johan Pieterse. Release `246d804` (tag v0.17.27), openric/service. This follows v0.17.26 (published-only read API) and closes the four gaps the PSIS session found while building the AHG Archives MCP's openric adapter.

## What changed

- **Hierarchy.** `GET /hierarchy/{id}` on a description now reads the AtoM tree (`information_object.parent_id`). Before, it read only `relation` rows, which hold no hierarchy for most records, so 829 (Engelbrecht Family Fonds) and 837 (the Bible inside it) both answered with no parent and no children. Parent, children and siblings are visible descriptions only, ordered by `lft`, each as `{@id, id, slug, title, level}`. A top-level description has no parent. Children are not paged yet (marked `ponytail:` in the code).
- **AtoM's root is hidden.** The root description (id 1, slug `kc4x-45tz-em84`, no title, published in the data) was listed as a record. That is the "404 slug" the adapter reported: it truncated the slug to `kc4x-45`. `Visibility` now always hides id 1, so the record list counts 402. OAI-PMH ListSets used to offer only the root as `fonds:1`, because it took sets to be descriptions with no parent. Sets are now the top-level descriptions (parent is the root, or no parent): 32 sets.
- **Autocomplete `types=`.** It took only internal keys (`io`, `actor`), so the documented example `types=place,agent,record` returned nothing for records and agents. It now also takes the names results carry and their plurals, in any case: record(s), agent(s), digitalobject(s), places, rules, activities, instantiations, repositories.
- **Record dates.** Only 3 AtoM events exist in the shared database. RiC-native descriptions date a record through the production and accumulation activities it results from (`rico:resultsOrResultedIn` / `rico:resultsOrResultedFrom` relations to `ric_activity` rows with start and end dates). `openricx:hasDateRangeSet` now includes those as `openricx:DateRange` objects, with date type `creation` (production) or `accumulation`, as mapping 7.2 asks. Activities with no date are skipped. 829 now carries 5 ranges, and the graph has 414 DateRange objects.
- **Revisions are skipped by the HideUnpublished scrub.** Their item ids are audit-row ids, which can collide with a hidden object id; the controller already checks the entity.

## Findings

- Agents were not a bug. The serializer sends `rico:history` and `rico:date` when the data has them, but only 21 of 423 agents have a history and 19 have dates of existence.
- The live graph after the rebuild has 26,435 triples. The previous graph is backed up at `storage/app/openric-graph/openric/backup-20261026-062513.nt`.
- Tests: `PublishedOnlyTest` now also covers the root, hierarchy and autocomplete types. The stale `RicoTermsTest` failure (it expects `openricx:isAssociatedWith`) is unchanged.
