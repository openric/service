# 2026-10-26 - v0.17.26: the public read API shows published descriptions only

Author: Dr Johan Pieterse. Commits `5666767` and the release `dba4484` (tag v0.17.26), openric/service.

## Why

While answering the PSIS session's request to connect OpenRiC to the AHG Archives MCP, a check showed that ric.theahg.co.za served drafts to anyone. OpenRiC reads the shared `heratio` database (403 published descriptions, 17 not published), and nothing in the read API looked at publication status. Before the fix, an anonymous GET of `/api/ric/v1/records/dr-aurelius-benson-copy` (a draft) returned 200. The live SPARQL graph held 420 descriptions, autocomplete returned draft titles, and OAI-PMH, relations, linked entities and thumbnails served drafts too. The only filter was OpenWriteFilter (open-write sandbox rows), on list endpoints only.

## What changed

- `AhgRic\Support\Visibility` holds the rule. A description is visible only when it has publication status Published (status type 158, status 160) and no other publication status. A draft, or a description with no status at all, is hidden (fail closed). Its digital objects and instantiations are hidden with it, and so are open-write entities. AtoM's root (id 1) is exempt.
- Queries: every list, autocomplete, relation list and OAI-PMH verb (ListRecords, ListIdentifiers, GetRecord, ListSets, ListMetadataFormats, Identify) leaves hidden ids out, so totals count published records only.
- 404: every by-key read answers a hidden entity exactly as a missing one, with the same problem+json body apart from `instance`. That covers records, export, agents, repositories, functions, places, rules, activities, instantiations, relations, relations-for, hierarchy, records/{id}/entities, entities/{id}/info, revisions, thumbnail and graph. relations-for, hierarchy, entities and revisions used to answer 200 with an empty body for an unknown id; they now answer 404.
- `AhgRic\Http\Middleware\HideUnpublished` sits on the whole `api/ric/v1` group. It scrubs every JSON GET response, removing nested nodes, edges and rows that name a hidden entity. It recognises a hidden entity by id or slug in reference keys (`@id`, `id`, `atomId`, `entity_id`, `openric:root`, `subject_id`, `object_id`, `target_id`, `record_id`, `source`, `target`, `target_uri`) and by this service's own IRIs, whatever their URI shape. It returns 404 when the whole document is about a hidden entity. Vocabulary, relation-types, sparql, openapi, health, conformance and stats are skipped: their ids are dropdown or term ids, which can collide with object ids.
- `openric:rebuild-graph` scrubs each document the same way, so the SPARQL graph is published-only. After release it was rebuilt with `--force`: 25,353 triples, 403 records. The previous graph was backed up to `storage/app/openric-graph/openric/backup-20261026-055431.nt`.
- `createRecord` (write API, import and seed) now writes a publication status through `StatusRow`, draft unless `publication_status` is `published`, as Heratio's V2 create does. Without this, API-created records would have had no status and stayed hidden forever. `openric:seed-demo` creates its records as published.
- Test: `packages/ahg-ric/tests/Feature/PublishedOnlyTest.php`. It fails against the old code and passes with the fix.

## Findings

- This checkout is the live service, and `vendor/ahg/ric` is a copy of `packages/ahg-ric`, so tests were run in a copy in the session scratchpad with the changed files mirrored into its vendor. The deploy was a hand-mirror into `vendor/ahg/ric`, new classes first and the routes file last.
- `RicoTermsTest::test_legacy_predicates_map_to_rico_1_1` is stale. It still expects `openricx:isAssociatedWith`, which d3d7f86 replaced with `rico:isRelatedTo` on purpose.
- The SSH remote rejects user johanpiet's key. Pushing over HTTPS with `gh auth git-credential` works.
- The citable page for a record is `/informationobject/<slug>`. It sends a browser (303) to viewer.openric.org and an API client to the JSON-LD.
- Not covered: files under `/uploads/` are served by nginx directly, so a draft's file is still reachable if its path is known. Places and activities that are linked only to a draft stay visible, because they have no publication status of their own.

## Follow-ups raised by the PSIS session (MCP openric adapter)

- `/hierarchy/{id}` returns no parent or children for records such as 829 and 837. The fallback reads `relation` rows, not `information_object.parent_id`.
- Some slugs that `/records` lists answer 404 on `/records/{slug}`, e.g. `kc4x-45`.
- `/autocomplete?types=Record` returns nothing.
- Records carry no dates in the JSON-LD, and agents carry only `rico:name`.
