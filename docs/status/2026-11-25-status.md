## Data-loss sweep

Every output key the serializer assigns was checked for being filled from two sources in one function, where the second would replace the first. One pair exists: a record's security classification and its access restrictions, both `rico:isOrWasRegulatedBy`, fixed and tested in v0.18.2. No key is set from a relation's predicate except the language predicate, so a relation cannot collide with it.

Found on the way, not a collision: a record's page (`/records/{slug}`) adds the security classification and access restrictions; its export (`/records/{slug}/export`, all three formats) does not call that step, so an export carried less than the page. On Dr Johan Pieterse's decision the same day, the export now runs that step on the record set and on every descendant, in all three formats (v0.18.5, tested in `IscapComplianceTest`). It adds these to every caller of the export, signed in or not, exactly as the record page already did.
